# XRD Phase-ID

A small GUI for screening a powder XRD pattern against a set of reference
patterns: does it look consistent with phase A, phase B, or a mixture?

It fits the sample as a **non-negative least-squares (NNLS) mixture of
reference patterns**, worked in Savitzky-Golay derivative space so the fit is
robust to background slope and to arbitrary intensity scaling. It also runs a
sanity check, independent of the fit, that looks at raw peak positions to warn
you when the fit can't be trusted — most importantly, when the sample has a
strong peak that none of your references explain (NNLS can't say "none of
these match"; it just gives the best available answer, which may be wrong).

**This is a screening tool, not quantitative phase analysis.** The fit weights
are coefficients, not phase fractions — see [Method and caveats](#method-and-caveats).

## Install and run

```bash
git clone <this-repo-url>
cd xrd-phase-id
pip install -r requirements.txt
streamlit run app.py
```

This opens the app in your browser (usually `http://localhost:8501`).

## Using it

1. In the sidebar, upload **reference patterns** — one CSV per phase, each two
   columns `2theta,intensity`.
2. Upload one or more **sample patterns** — whitespace-separated
   `2theta intensity`, one point per line (the standard `.xy` export format
   from most XRD software).
3. Optionally upload **candidate patterns**: phases you suspect might be
   present but don't want in the fit. These are never fit — they're only
   searched for suggestions when the sample has unexplained peaks.
4. Click **Run fit**.

Don't have data handy? Tick **"Use bundled synthetic demo data"** in the
sidebar to try the tool on a synthetic ~70/30 calcite/quartz mixture (see
[Demo data](#demo-data) — this is fabricated data for trying the tool, not a
real measurement).

## Method and caveats

- **What the fit does.** Each pattern is normalised by total area, then
  differentiated with a Savitzky-Golay filter. The sample's derivative is
  fit as a non-negative mixture of the reference derivatives (`scipy.optimize.nnls`).
  Derivative space is what makes the fit insensitive to a sloping background
  and to how the intensities happen to be scaled.
- **NNLS always returns an answer.** It cannot say "none of these references
  match this sample." If the true phase is absent from your reference set, the
  weight goes to whichever reference correlates best — a confident-looking
  number for a phase that isn't actually there. **Always check the sanity
  check panel before trusting a weight.** It's computed independently of the
  fit, purely from peak positions: it flags patterns with too little signal to
  identify anything (`peak/background` below ~6), and peaks in the sample that
  none of your references explain.
- **Weights are not phase fractions.** They're NNLS fit coefficients,
  normalised to sum to 1. Say "mostly consistent with X", not "34% phase X".
  Quantitative phase analysis needs Rietveld refinement with a
  preferred-orientation correction — platy/layered phases especially can
  redistribute intensity in ways a fixed-intensity template match gets wrong.
- **Residual RMS is not a trust signal.** Area-normalised intensities are
  small to start with, so a small residual doesn't mean much on its own; trust
  the sanity check, not the residual.

## Demo data

`demo_data/` contains synthetic patterns generated by
`scripts/generate_demo_data.py` — Gaussian peaks placed at commonly published
Cu-Kα reflection positions for calcite, quartz and halite, plus noise and a
sloping background. They are **not measured or database-derived patterns**,
just illustrative data so the app has something to fit out of the box.
Regenerate or extend them with:

```bash
python scripts/generate_demo_data.py
```

For real reference patterns, a good public source is
[RRUFF](https://rruff.info/) (check their terms before redistributing
anything you download from it).

## Project layout

```
app.py                          Streamlit GUI
xrd_phase_id/
  io_utils.py                   reading .xy samples and reference CSVs
  fit.py                        area normalisation, S-G derivative, NNLS fit
  sanity.py                     peak finding + independent sanity check
  plotting.py                   the 4-panel fit figure
demo_data/                      synthetic demo dataset (see above)
scripts/generate_demo_data.py   regenerates demo_data/
tests/                          unit tests for fit.py / sanity.py
```
